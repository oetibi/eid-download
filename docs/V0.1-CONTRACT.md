## Quality policy (owner: no 8K)
Fixed choices: `360p, 480p, 720p, 1080p, 1440p, 2160p (4K)`, `best` (= best available up to 2160p),
`audio` (audio only, mp3). Anything taller than 2160 is refused everywhere (CLI, IPC, GUI, extension).
Fallback when the requested height is not available: take the tallest available format **not taller
than** the request; if none exists, take the shortest available one; the job reports the height it
actually got (`got_height`) so the UI can show "requested 1440p, got 1080p".

## Tauri commands (GUI window -> app). JSON field names are exact.
Existing (unchanged names): `list`, `add`, `pause`, `resume`, `remove`, `clear_finished`, `pick_folder`, `reveal`.

`list` (engine-perf may extend; must stay backward compatible): accepts optional `{ since: number }`
(a revision). Returns `{ rev, full, items, removed, counts, ... }`. When `since` is absent or too
old, `full = true` and `items` is every item; otherwise `items` holds only items changed since
`since` and `removed` the ids gone. UI keys rows by `id`.

New (playlists branch implements, UI branch consumes; mock.js must simulate them):
- `video_probe({ url })` -> `{ kind: "video"|"playlist", title, uploader?, duration?,
   qualities: ["360p",...,"2160p","best","audio"],  // only those actually available + best + audio
   items?: [{ index, id, title, duration? }] }`   // playlist only, in playlist order (index from 1)
  Runs off the UI thread (async / spawn_blocking). Errors are `Err(String)` with a short message.
  If yt-dlp/FFmpeg are not installed yet, returns Err with prefix `TOOLS_MISSING:`.
- `tools_status()` -> `{ installed: bool, consent: bool, ytdlp_version?, ffmpeg_version? }`
- `tools_install({ accept: true })` -> starts the on-demand download of the pinned tools (consent
   recorded); progress shows through `video_jobs`/`tools_status`.
- `video_add({ url, quality, dir? })` -> `{ job }`
- `playlist_add({ url, quality, items?: [index...], dir? })` -> `{ job }` (items absent = all).
   Creates a playlist folder, numbered files `001 - Title.ext` in playlist order, skips finished items.
- `video_jobs()` -> `[{ job, kind, title, state: "queued"|"running"|"paused"|"done"|"failed",
   quality, got_height?, done_items, total_items, failed_items, bytes?, total_bytes?, speed?,
   items?: [{ index, title, state, progress (0..1), got_height?, error? }] }]`
- `video_pause({ job })`, `video_resume({ job })`, `video_retry({ job })` (retries failed items only),
  `video_remove({ job })`.
Job state persists across restarts (playlists already persist `.eid-playlist.json`).

## IPC / Native Messaging (eid-ipc proto, browser allow-list)
New `Command` variants, allowed from the browser: `probe { url }`, `add_video { url, quality }`,
`add_playlist { url, quality, items?: [u32] }`. Results mirror `video_probe` / `{ job }`.
Quality strings are exactly the policy list above; anything else is rejected by `validate()`.
Never allowed from the browser: `shutdown`, `show`, `list`, `pause`, `resume` (unchanged).

## Additions after integration (2026-11-19, dev/v0.1)
- `tools_consent_text({ lang: "ar"|"en" })` -> string: the full agreement text the window shows in
  its own consent dialog before `tools_install({ accept: true })`. The install button stays
  disabled until the user ticks the box; nothing is downloaded on cancel.
- `tools_status()` also returns `deno_version?`.
- `video_jobs()` items: a failed item has `state: "failed"` and `error`; the job's own `error`
  names the failed items. Playlist progress in the UI = finished items / total items (never the
  current item's bytes).
- `settings_get()` -> `{ max_parallel (1..8), connections (1..32), speed_limit_kib (0 = none,
  <= 12500000), schedule: null | { start_min, end_min (0..1439, start != end), weekdays (bit 0 =
  Monday ... bit 6 = Sunday, != 0) } }`. Unknown fields are refused.
- `settings_set({ settings })` -> the saved settings. Validates, saves to
  `<config>/gui-settings.json`, then applies at once: queue limit and window, global speed limit;
  the connection count applies to downloads that start after the change.
- `open_file({ id })`: opens a finished file with its default program. Executables and scripts
  (`exe msi bat cmd ps1 js vbs scr lnk …`, and names ending in "." or " ") are never opened:
  their folder is shown and the error is `refused_executable`. Missing file: `file_missing`.
