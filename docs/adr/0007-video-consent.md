# ADR-0007: موافقة المستخدم قبل أدوات الفيديو
**الحالة:** مقبول (رسمة المستخدم: «الفيديو، بموافقتك»؛ زاجل تفعل الشيء نفسه — ADR-0009 عندهم).
**القرار:** لا تنزيل ولا تشغيل لـyt-dlp/FFmpeg/JS runtime قبل نافذة موافقة (عربي/إنجليزي) تذكر الأدوات وإصداراتها ومصدرها الرسمي والتحقق بـSHA-256 ومسؤولية المستخدم عن الحقوق، ورفض DRM. تُخزَّن الموافقة (نسخة النص + وقت) ويمكن سحبها (تحذف الأدوات). CLI: يسأل مرة، أو `--yes-i-agree`. إضافة المتصفح لا تعرض زر الفيديو قبل الموافقة. الأدوات **تُنزَّل فقط** من الإصدار الرسمي بعد الموافقة (لا نعيد توزيعها داخل مثبّتنا، فلا التزامات إعادة توزيع GPL/LGPL علينا) وتُثبَّت بإصدار وبصمة؛ تُفحص البصمة قبل كل تشغيل؛ لا تحديث صامت.

**تعديلات المالك (2026-11-15، القرارات D1/D2/D11 في [plans/P4.md](../plans/P4.md)):**
- **D2 — علم CLI:** `--yes-i-agree` (لا `--yes`). بلا TTY وبلا هذا العلم ⇒ رفض فوري لا انتظار. IPC وNative Messaging لا يمنحان الموافقة أبداً (أوامر الفيديو عبرهما مؤجَّلة إلى P5/P6، D7).
- **السجل:** `settings.json` → `media_consent = {version, text_sha256, ts}` في ملف خاص؛ النص من ملفات الترجمة (ar/en) وبصمته تُخزَّن، فتغيّر النص يتطلب موافقة جديدة.
- **D1 — «المصدر الرسمي» لـFFmpeg/ffprobe:** ffmpeg.org لا ينشر بناءً لـWindows، فالمصدر = إصدارات **BtbN/FFmpeg-Builds** على GitHub: فرع n8.1، **LGPL**، win64 ثابت (غير shared)، مثبَّت على **وسم مؤرَّخ** (`autobuild-…`) لا `latest`، والبصمة من `checksums.sha256` لذلك الوسم. yt-dlp وDeno من إصداراتهما الرسمية على GitHub.
- **تعديل D1 (ملاحظة المراجعة M6، بموافقة المالك 2026-11-17):**
  - **مصدر FFmpeg طرف ثالث، لا بناء رسمي من مشروع FFmpeg.** هو بناءات المطوّر `BtbN` (حساب GitHub رقم 294293، منذ 2010). مشروع FFmpeg لا ينشر بناءً لـWindows، و«المصدر الرسمي» في D1 يعني صفحة إصدارات هذا المزوّد فقط.
  - **العنوان المعتمد:** `github.com/FFmpeg-Builds/FFmpeg-Builds`. نقل `BtbN` المستودع في 2026-11-07 إلى المنظمة `FFmpeg-Builds` (رقمها 353825010، أُنشئت في اليوم نفسه، غير موثَّقة على GitHub، وبلا أعضاء علنيين).
  - **أدلة أنه المستودع نفسه، لا نسخة جديدة** (معلومات GitHub العامة، 2026-11-17، بلا تنزيل أي ملف تنفيذي):
    1. المعرّف نفسه 292087234، وتاريخ الإنشاء نفسه 2020-09-01.
    2. `github.com/BtbN/FFmpeg-Builds` يعيد 301 إلى العنوان الجديد، و`api.github.com/repos/BtbN/FFmpeg-Builds` يعيد 301 إلى `repositories/292087234`. أي أنه نقل للمستودع نفسه.
    3. commit `6a4fd78e` («FFmpeg-Builds repo moved into its own org») كتبه الحساب `BtbN`، وكذلك كل commit بعده.
  - **الإصدار المثبَّت لم يتغير:**
    - الوسم `autobuild-2026-11-14-12-37` بناه `github-actions[bot]` داخل المستودع.
    - بصمة الأرشيف في `checksums.sha256` لذلك الوسم تطابق بصمة GitHub للأصل، وتطابق `tools/manifest.json`: `9a1c8c9f…e56c`، الحجم 167 647 869 بايت.
    - بصمة ملف `checksums.sha256` نفسه تطابق بصمة GitHub له (`66b81ba7…`).
    - هذا التعديل لا يغيّر الإصدار ولا أي بصمة.
  - **حدود:**
    - لا تُعرف هوية من يملك صلاحيات المنظمة.
    - الـcommits غير موقَّعة.
    - `checksums.sha256` من الناشر نفسه، فهو يثبت سلامة الملف لا أمانة الناشر.
    - إصدارات GitHub هنا قابلة للاستبدال (`immutable: false`). الحماية هي البصمة المثبَّتة: أي ملف مختلف يُرفض.
  - **عند أي تحديث لإصدار FFmpeg:** يُعاد هذا الفحص كله (المالك، والاستمرارية، و`checksums.sha256`) قبل تغيير أي بصمة، ويحتاج موافقة المالك (AGENTS §8).
- **D11 — تفسير «تُفحص البصمة قبل كل تشغيل»:** عند بدء كل مهمة تُفتح كل أداة بمقبض **مشاركة قراءة فقط** (لا `FILE_SHARE_WRITE` ولا `FILE_SHARE_DELETE`)، وتُحسب البصمة **عبر هذا المقبض نفسه**، ويبقى المقبض مفتوحاً حتى تنتهي شجرة العمليات كلها. على Windows يمنع هذا الكتابة والحذف وإعادة التسمية (وإعادة تسمية المجلدات الأب) بين الفحص والتشغيل، بينما يبقى `CreateProcess` ممكناً (تحقّق منه المالك على Windows 10 19045/NTFS، ويُعاد باختبار على Windows CI). ملف مفتوح للكتابة قبلنا ⇒ يفشل القفل ⇒ نرفض. **حدود موثّقة:** Linux بلا قفل مكافئ؛ ملفات `_MEI…` التي يفكها `yt-dlp.exe` (onefile) في `%TEMP%` خارج البصمة والقفل؛ المدير/SYSTEM يتجاوزان الأقفال؛ مهاجم بنفس المستخدم خارج نموذج التهديد.

**الدليل:** P4: اختبار أن `eid video` بدون موافقة لا يشغّل شيئاً ولا يتصل بالشبكة؛ اختبار فشل بصمة خاطئة؛ اختبار عدم تنفيذ أداة من PATH. الأسماء المسمّاة في PLAN «بوابات P4» (G2، G3)، ومنها `no_tty_and_no_flag_refuses_consent_without_waiting` و`tool_hash_is_read_through_the_locked_handle` و`windows: tools_are_locked_against_write_delete_rename_while_a_job_runs`.
