1. **B — yt-dlp owns YouTube transfer and muxing.** Extraction-only makes us responsible for chunk sizing, signed URLs, request context, fragments, and refresh. Current [extractor code](https://raw.githubusercontent.com/yt-dlp/yt-dlp/master/yt_dlp/extractor/youtube/_video.py) and [PO-token guidance](https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide) show why that boundary matters. **Rule:** YouTube always uses yt-dlp; our engine handles ordinary HTTP files. Persist source URL plus format policy; re-extract when starting/resuming, never assume six-hour validity. Use stream-copy only with compatible containers. Our queue supervises yt-dlp; reserve media bandwidth explicitly—its limiter cannot share Rust’s token bucket.

2. **A — SChannel on Windows.** This removes ring’s C-build requirement from this dependency path and uses Windows trust policy; the whole MSVC build still needs target libraries/linking. **Rule:** pin reqwest 0.12; target-specific dependencies, `default-features=false`, Windows features `["native-tls-alpn","stream","json"]`, Linux `["rustls-tls","stream","json"]`. Audit feature unification; force `.http1_only()` for segmented transfers. [Features](https://docs.rs/crate/reqwest/0.12.24/features)

3. **C — ramp gradually; retain round-1’s acknowledged handoff.** **Rule:** keep probe body as worker 0 after valid 206/total/identity. Every 300 ms add one worker toward default 8, maximum 32, subject to origin cap. Split largest unwritten remainder only if ≥8 MiB; each half ≥4 MiB. Send victim a pause command; it finishes its current positional write, stops reads/writes, and acknowledges cursor `p`. Coordinator halves `[p,end)`, publishes generation-tagged leases, then resumes victim and dispatches tail. No atomic-end-only shortcut. Reconnect after 15 seconds below ¼ peer median, excluding limiter/disk waits; cancel and await writes first; maximum twice/minute. Repeated concurrency-correlated 429/resets halve origin cap for 24 hours; honor Retry-After. A lone 403 triggers authentication/expiry diagnosis.

4. **C — JSON acceptable; SQLite remains my preference.** Twenty thousand mostly inactive jobs is fine; rewriting twenty thousand every checkpoint is not. **Rule:** one writer; checkpoint dirty active jobs every 2–5 seconds. Freeze checkpoint offsets, complete writes, `sync_all` data, then serialize those offsets into unique same-directory temp; sync and close it. Close metadata readers or allow delete-sharing. Use [ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) with `.bak`; rename for first creation. Retry sharing violations with bounded jitter; never delete destination first. On failure retain old checkpoint and report degraded persistence. Validate schema/generation/coverage; quarantine invalid files and recover backup. Atomic replacement alone does not guarantee power-loss durability.

5. **A — sparse before logical sizing.** **Rule:** attempt [FSCTL_SET_SPARSE](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_set_sparse), then `set_len`; sparse allocates blocks as written, reserving no capacity. FAT/exFAT lack sparse support; network support depends on server/filesystem. Unsupported: use sequential growing-file fallback for v1. Enforce FAT32’s file-size limit; handle ENOSPC throughout. “Every non-sparse set_len immediately zero-fills” is too categorical.

6. **C — explicit DACL plus token defense.** “0-ACL” is incorrect: empty DACL denies everyone; NULL DACL permits everyone. **Rule:** protected user-only DACL on pipe/token directory, reject remote clients, first-instance protection, random 256-bit token and bounded handshake. Token does not protect against same-user malware. A per-user startup mutex elects one app; hosts retry readiness with deadline, then submit idempotent request IDs. [Pipe security](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)

7. **C — reject unsafe extrapolations.** No 64-byte overlap proves representation identity; restart without trustworthy validation. Shortening an HTTP/1.1 response usually forfeits connection reuse unless drained. IDM documents splitting, not these precise timings. No unlimited retries, automatic credential-stripping fallbacks, or assumption that writing MotW guarantees SmartScreen evaluation.

8. **B — tests first, in this implementation order:** range/identity validation; split/cancel/write races; flush/checkpoint/crash recovery; Windows sparse/ENOSPC/rename collisions; IPC startup/authentication/idempotency. Each can silently corrupt data or duplicate work.
